# P4 — Mobile + Code Audit: Risks & Mitigations

Phase spec: PRODUCT_BLUEPRINT.md §2, ENTERPRISE_SPEC.md §10
Branch: `phase/p4-mobile-code`

## Risks

1. **BLOCKER-IF-ABSENT — Android toolchain binary.** `aapt2`/`apktool` must be installed locally and on whatever host runs the verifier. Vercel serverless won't ship these. **Mitigation:** ship a pinned `Dockerfile`/`scripts/install-android-tools.sh`; in CI, install tools before verify. Mark BUILD-time test as skippable only if `AAPT2_PATH` env unset (never in CI). Flag in PR body.

2. **BLOCKER-IF-ABSENT — iOS toolchain.** `7zip`/`plist` parsing on Windows is non-trivial; `Info.plist` binary format needs `bplist` parser. **Mitigation:** stub iOS path returning `[]` with a logged warning — don't fail build. Document as a follow-up ticket in PR body.

3. **APK size bomb.** Uploading `.apk` up to 200MB can OOM Supabase storage/edge function. **Mitigation:** enforce size guard at upload `route.ts`, stream to private evidence bucket (not memory), reject >200MB with 413. Add test `__tests__/apk-upload-too-big.test.ts`.

4. **APK path traversal.** `apktool` d-extract could write outside sandbox on malformed APK. **Mitigation:** extract inside a `mkdtemp` dir; verify all extracted paths stay inside sandbox; reject otherwise. Add test for `../../` entry names (`__tests__/apk-traversal.test.ts`).

5. **Code-clone SSRF.** A malicious `git` URL could target `169.254.169.254` metadata or internal hosts. **Mitigation:** extend `lib/ssrf.ts` to resolve the clone host BEFORE `git clone`; reject private/loopback/link-local IPs; reject `file://`, `ssh://` to non-public hosts (ssh hard to validate — prefer https). Add test `__tests__/ssrf-code.test.ts`.

6. **Repo clone disk bomb.** A huge repo or `git history` clone fills disk. **Mitigation:** `--depth 1`, `--single-branch`, `--no-tags`; set `git fetch` timeout (5 min); cap repo size at 500MB post-checkout and abort with cleanup. Add `__tests__/clone-cap.test.ts`.

7. **Code-lint false positives.** Pinned linters may emit noise. **Mitigation:** LLM never filters findings; the wrapper only converts lint output to rows verbatim. Reviewer adjusts config in committed `.linterrc` — fix the rule, not the wrapper. Document in RISKS only — no code change needed this phase.

8. **APK fixture portability.** A real `.apk` is binary and large; committing one bloats the repo. **Mitigation:** commit a minimal `__fixtures__/sample-appk.apk` built with `aapt2` ≤10KB, generated by `scripts/build-fixture-apk.sh` (added this phase). If size >100KB, regenerate. Add test asserting fixture ≤100KB (`__tests__/fixture-size.test.ts`).

9. **Vercel serverless limits.** APK parse + code clone are long-running (>10s) — Vercel hobby function max is 10s for synchronous. **Mitigation:** both run via **Inngest** background steps, not in route handlers. Routes only enqueue. Add test asserting route returns 202 with job id.

10. **`path-to-regexp` Next.js 16 routing change.** P1 tasks didn't touch `platform` field; adding it to existing `[auditId]` routes must not break `useParams`. **Mitigation:** add `platform` as query/form field, not URL segment, until P6 if needed. Test `__tests__/mobile-scope.test.ts` covers both web and android entries using existing route.

11. **Pinned axe-core interaction.** Code-lint against committed HTML must use the SAME pinned axe-core version as web scans (consistency). **Mitigation:** import `axe-core` version from `package.json` in `lint-runner.ts` (don't re-pin separately). Add test `__tests__/axe-version-parity.test.ts` asserting identical version string.

12. **Supabase RLS on new tables.** `mobile_artifacts` and `code_repos` tables need RLS deny-all + owner-only policies or the guardrail weakens. **Mitigation:** migration includes RLS block mirror of P0 `findings` policy; add test `__tests__/rls-mobile-code.test.ts` asserting cross-user SELECT returns empty.
