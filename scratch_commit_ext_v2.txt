Rebuild Chrome extension as a shadcn side panel with real feature parity

Full rearchitecture per feedback: the v1 popup used ad-hoc vanilla-JS UI
that didn't match the site's design system, and covered a fraction of
what the workbench's Inspect/Accessibility tools actually do.

- Real React + shadcn UI, not a re-implementation: the side panel imports
  the actual Button/Card/Badge/Tabs/Accordion components and the real
  AccessibilityOptionsPanel (variant="inline") directly from ../src via a
  Vite "@" alias — same components, same accessibility behavior, same
  visual design as the website. No new UI library, no duplicated styling.
- Chrome's native Side Panel API (chrome.sidePanel) instead of a popup —
  persists while browsing instead of closing on outside click, matching
  the "side drawer" ask. background.ts just wires
  setPanelBehavior({openPanelOnActionClick: true}).
- Audit tab now produces the same WCAG compliance-matrix report the
  workbench does: extractFindings + computeComplianceMatrix + the real
  wcag-registry (extracted to engine/finding-mapping.ts in the prior
  commit specifically so this could reuse the exact rule-id -> SC mapping,
  not a re-derived approximation), grouped by principle with pass/fail/
  needs-review/manual status per criterion. A native keyboard/focus-order
  walkthrough (content-script.ts) contributes a real WCAG 2.4.7 finding
  when live .focus() traversal finds an element with no visible focus
  indicator — Playwright itself can't run inside a content script (it's a
  Node library driving a browser externally), so this replicates what
  engine/keyboard.ts checks server-side using the browser's own focus
  APIs directly against the real open tab, which is arguably more
  authentic than a synthetic session.
- Inspect tab: click-to-pick (content script owns the on-page hover/click
  since the side panel is a separate execution context, not an iframe —
  pushes the picked element back via a runtime message), full contrast
  verdict via the real contrastRatio/contrastVerdict from lib/contrast.ts,
  a live focus-order walkthrough with step controls, and a contrast-pairs
  scan across the page.
- Content script bridges the side panel to the live page (chrome.runtime
  messaging, all async — unlike bridge-script.ts's synchronous
  window.postMessage-based bridge for a same-origin iframe, this is a
  genuinely different execution-context boundary, so the message
  vocabulary is adapted, not literally shared code).
- @types/chrome added; chrome-extension gets its own tsconfig.json (root
  tsconfig now excludes it) since chrome.* globals don't belong in the
  Next.js app's type-checking scope.
- New root script: npm run build:extension (three separate Vite builds —
  side panel as ES modules, content-script and background as IIFE, since
  Rollup's multi-input + iife combination isn't supported).
