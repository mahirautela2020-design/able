Add fast PSI/Lighthouse accessibility preview (parallel, non-blocking)

New "audit/psi-preview" Inngest function (src/inngest/functions/psi-preview.ts)
calls Google PageSpeed Insights (src/lib/psi.ts), which runs Lighthouse
server-side, and writes score/screenshot/top-issues into a new fast_preview
jsonb column (migration 0005). Fired alongside the existing audit/url event
in POST /api/audits, with its own concurrency group and zero retries so it
can never block or be blocked by the real axe+Playwright pipeline (which
has concurrency:1) -- purely best-effort, any failure just leaves
fast_preview empty.

Workbench shows it in the left column while the full audit is still
queued/running: score badge, screenshot, top failed checks. Same rule
engine as our own scan (Lighthouse's accessibility category wraps axe-core
too), so it is explicitly framed as a preview, not a replacement -- it
skips keyboard testing, AX-tree/SR simulation, responsive re-scan, and
contrast lab, all of which only the full pipeline does.

Note: PSI (pagespeedonline.googleapis.com) and CrUX
(chromeuxreport.googleapis.com) are different Google APIs -- CrUX is
field-only Core Web Vitals with no accessibility data, so it isn't used
here.
